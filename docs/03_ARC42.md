## 1. Introduction and Goals

### 1.1 Requirements Overview

Pharma LIMS replaces paper-based QC laboratory workflows with a 21 CFR Part 11-compliant electronic system. It manages the full sample lifecycle — from registration through testing, QA review, and CoA release — enforcing regulatory compliance at every step.

### 1.2 Quality Goals

| Priority | Quality Goal | Motivation |
|---|---|---|
| 1 | **Data Integrity** | ALCOA+ — every result attributable, contemporaneous, original, accurate, complete |
| 2 | **Regulatory Compliance** | 21 CFR Part 11, EU GMP Annex 11, ICH Q1A |
| 3 | **Auditability** | Every action traceable to a person, timestamp, and old/new values |
| 4 | **Security** | E-sig with independent password re-entry; login lockout; role separation |
| 5 | **Maintainability** | Clean Architecture + CQRS — change one module without touching others |

### 1.3 Stakeholders

| Role | Concern |
|---|---|
| QC Analyst | Fast, accurate result entry; clear work queue; ALCOA+ enforcement |
| QA Officer | Compliant audit trail; CoA integrity; OOS investigation closure |
| Lab Manager | WAP resource planning; TAT visibility; instrument utilisation |
| IT / Admin | Deployment, backup, user management, config |
| Regulator (FDA/EMA) | 21 CFR Part 11 evidence; audit trail completeness; e-sig records |

## 2. Architecture Constraints

| Constraint | Rationale |
|---|---|
| PostgreSQL 16 | Azure-hosted; EF Core code-first; snake_case table names |
| .NET 8 | LTS; Clean Architecture; CQRS + MediatR |
| React 19 + TypeScript | Existing skill set; Vite dev server |
| No hardcoded values | 21 CFR Part 11 Contract 2 — all config from `lab_config` table |
| INSERT-only audit tables | 21 CFR §11.10(e) — no UPDATE or DELETE on compliance records |
| BCrypt password on every e-sig | 21 CFR §11.300 — session token alone insufficient |
| UTC timestamps server-side | ALCOA+ Contemporaneous — no client-supplied timestamps |

## 4. Solution Strategy

| Decision | Strategy |
|---|---|
| **Architecture style** | Clean Architecture (Domain → Application → Infrastructure → API) |
| **Command pattern** | CQRS via MediatR — commands mutate state; queries read state |
| **Single source of truth** | `digital_logbook_entries` is the authoritative results store |
| **No business logic in React** | All computation server-side (.NET) |
| **Compliance by design** | Every ALCOA+ principle enforced by a named service class |
| **Configurable, not coded** | All thresholds, formats, time-slots from `lab_config` table |

## 6. Runtime View

### 6.1 Sample Registration (happy path)

```
Analyst → POST /samples
  → SampleValidatorService (5 checks)
  → ISampleIdFormatService.Generate()
  → IFormTemplateSelectorService.Select()
  → INSERT samples
  → return 201 Created

Analyst → POST /samples/{id}/sign-srf
  → IElectronicSignatureService.CreateSignature()
      → BCrypt.Verify(password) ← §11.300
      → INSERT electronic_signatures
  → sample.Status = 'PendingTesting'
  → return 200 OK
```

### 6.2 Per-Execution Re-assign

```
Lab Manager → POST /test-executions/{id}/assign
  → AssignTestMethodCommand handler
  → Check execution.Status == 'Assigned'
  → Check analyst training not expired  → error: TRAINING_EXPIRED
  → Check instrument calibration current → error: INSTRUMENT_OOC
  → UPDATE test_executions (analyst_id, instrument_id, priority_score)
  → return 200 OK
```

### 6.3 Post-Sign Amendment

```
Analyst → POST /digital-logbook/{id}/amend
  → AmendLogbookEntryCommand handler
  → Check entry.Status == 'Signed'
  → BCrypt.Verify(password)  → error: ESIGN_AUTH_FAILED
  → INSERT electronic_signatures (amendment signature)
  → UPDATE original entry: status='Superseded', amendment_reason, amendment_sig_id
  → INSERT new entry: status='Pending', new raw_value
  → return 200 OK
```

## 8. Cross-Cutting Concepts

### Compliance

- All audit records INSERT-only (DB-level trigger enforcement)
- UTC timestamps on all compliance fields (`TIMESTAMPTZ DEFAULT NOW()`)
- BCrypt.Verify on every e-sig independent of JWT session

### Error Handling

- Machine-readable error codes (`ESIGN_AUTH_FAILED`, `TRAINING_EXPIRED`, etc.)
- HTTP 422 Unprocessable Entity for business rule violations
- HTTP 423 Locked for account lockout
- All exceptions caught at controller level; ProblemDetails format

### Background Jobs (13 IHostedService)

| Job | Interval | Purpose |
|---|---|---|
| CalibrationDueDateJob | Daily | OOC detection; T-7/T-1 alerts |
| TrainingExpiryJob | Daily | Expiry check; T-7 alert |
| TATBreachJob | Hourly | TAT overdue detection |
| PullReminderJob | Daily | Stability pull T-7/T-1 |
| DestructionAlertJob | Daily | Retain sample alerts |

## 9. Architecture Decisions

*See `09_ADRs.md` for full decision records.*

Key decisions:
- ADR-001: PostgreSQL over SQL Server (Azure-native, open source)
- ADR-002: Clean Architecture + CQRS (testability, separation of concerns)
- ADR-003: INSERT-only audit at DB level (compliance non-negotiable)
- ADR-004: No SignalR in v1 (simplified deployment; polling acceptable for MVP)
- ADR-005: Groq (not Azure OpenAI) for AI features (cost + latency)

|---|---|---|---|

## 11. Technical Risks

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Azure DB connectivity loss | Low | High | Retry policy (5 retries, 10s max delay); connection pooling |
| EF migration failure in production | Medium | High | Migration scripts reviewed before deployment; rollback script ready |
| Groq API outage | Medium | Low | Chatbot only; no core workflow dependency |
| JWT secret rotation | Low | High | Documented key rotation procedure; all tokens invalidated on rotation |
| Large audit table performance | Medium | Medium | Partial index on `changed_at`; archival policy after 7 years |
