## Governance Contracts

### Contract 1 — General Architecture
- **No code duplication.** Every business rule owned by exactly one named service class. FK-only references — no master data copied into consuming tables.
- **Single source of truth.** `digital_logbook_entries` drives Results Management, QA Review, CoA, and Traceability. No separate results store.
- **DB-portable.** Clean BE/FE/DB separation. No business logic in React or stored procedures.
- **No dead code.** Inactive records use soft-delete (`is_active = FALSE`). Never physically deleted.

### Contract 2 — Backend Services
- **All compute on server** (.NET Core 8). React renders — never computes.
- **All push via SignalR** from server. No polling — no `setInterval`, no repeated GET.
- **No hardcoded values.** Every threshold, timing, format from PostgreSQL.
- **Normalizer views** (`vw_*` prefix). Same view drives every UI panel.
- **UTC timestamps server-side** on all compliance records (ALCOA+ Contemporaneous).

### Contract 4 — Authentication & Access Control
- **Login page:** username · password · forgot-password link · remember-me checkbox — **all four mandatory.**
- **First run:** Tenant Admin creation before any other user or module access.
- **Two user types only:** Admin and Regular User. Roles are Regular User variants with explicit write grants.
- **Segregation of duties** enforced by system.

## 1. Purpose & Scope

Sample Registration is the entry point for all LIMS lab work. Two paths: (1) analyst registers on material receipt, (2) Checkpoint pull auto-creates the sample. Both paths run the same **5 GMP pre-checks** via `SampleValidatorService` (Contract 1 — no duplicate validation logic). v1.2 adds: **barcode label auto-printed at Step 4** (immediately after record creation, before validation gate) — the chain of custody anchor; **configurable Sample ID format** from `lab_config` (Contract 2); **Form Template auto-selected server-side** by `IFormTemplateSelectorService` (Contract 1 — no UI dropdown required from analyst).

## 3. Registration Workflow — 7 Steps

| Step | Name | Key Rule | Actor |
|---|---|---|---|
| 1 | Login & Site | Role-based access (Contract 4) | Analyst |
| 2 | Material Receipt | Select material from Master Data. Log Lot No, Quantity, Supplier, MFG/EXP dates. | Analyst |
| 3 | Create Sample Record | Sample ID generated by `ISampleIdFormatService` using `lab_config` template (Contract 2). | System |
| **4** | **Barcode Label Printed** | **QR/barcode auto-generated + sent to printer. Pre-linked to Sample ID, lot, test list. Before validation gate. NEW v1.2** | System |
| 5 | Validation Gate | 5 GMP checks: lot not expired · approved spec exists · instrument calibrated · analyst trained · reagent in stock. All via `SampleValidatorService` (Contract 1). Hard block on any failure. | System |
| 6 | Assign Tests & Form Template | Spec-driven test assignment. `IFormTemplateSelectorService` (Contract 1) selects Form Template server-side. No UI dropdown. | System |
| 7 | SRF & Work Queue | SRF auto-generated. Analyst e-signs §11.50. Status → PENDING TESTING. SignalR push (Contract 2). | Analyst |

## 4. Barcode Label Content Specification

| Field | Source | Compliance Purpose |
|---|---|---|
| Sample ID (QR + human-readable) | Server-generated by `ISampleIdFormatService` | Scan at any point opens correct Work Queue task |
| Material Name + Lot Number | From Material Receipt step | Lot traceability anchor |
| Test List (abbreviated) | Auto-assigned tests from Spec | Analyst knows expected tests |
| Date Registered + Analyst Name | Server UTC + `users.full_name` | ALCOA+ Attributable + Contemporaneous |
| Site Code + Lab Code | From Lab Master Data | Multi-site differentiation |
| Form Template Reference | Short code (e.g. `LAB-F-10`) | Links label to active Form Template for barcode scan at test start |

## 5. Configurable Sample ID Format

Sample ID format is configured per site/lab in `lab_config` (Contract 2 — no hardcoded format). `ISampleIdFormatService` generates the ID server-side.

```
config_key   = 'sample_id_format'
config_value = '{SITE}-{MAT}-{DATE}-{SEQ}'       --> KLAB-H2SO4-20260511-0042
             = '{LAB}-{SAMPLETYPE}-{YYYYMMDD}-{SEQ4}'  --> QC-RM-20260511-0042
             = '{SITE}-{LOT}-{SEQ3}'             --> PLT1-LOT230A-042

Available tokens: {SITE} {LAB} {MAT} {SAMPLETYPE} {DATE} {YYYYMMDD} {LOT} {SEQ} {SEQ3} {SEQ4}
```

## 7. Data Model (PostgreSQL 16)

```sql
CREATE TABLE samples (
  sample_id          SERIAL PRIMARY KEY,
  sample_number      VARCHAR(60) NOT NULL UNIQUE,  -- configurable format (Contract 2)
  lab_id             INT NOT NULL REFERENCES laboratories(lab_id),
  material_id        INT NOT NULL REFERENCES materials(material_id),
  lot_number         VARCHAR(100) NOT NULL,
  mfg_date           DATE NOT NULL,
  exp_date           DATE NOT NULL,
  sample_type        VARCHAR(50) NOT NULL,
  form_template_id   INT REFERENCES form_templates(form_template_id), -- auto-selected
  status             VARCHAR(30) NOT NULL DEFAULT 'Registered',
  -- Registered | PendingTesting | InTesting | PendingQAReview | Released | Rejected
  barcode_printed    BOOLEAN NOT NULL DEFAULT FALSE,
  barcode_printed_at TIMESTAMPTZ,
  srf_signature_id   INT REFERENCES electronic_signatures(signature_id),
  due_date           TIMESTAMPTZ,  -- server-calculated from DB TAT config
  analyst_id         INT NOT NULL REFERENCES users(user_id),
  created_at         TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE barcode_print_log (
  print_id    SERIAL PRIMARY KEY,
  sample_id   INT NOT NULL REFERENCES samples(sample_id),
  print_type  VARCHAR(20) NOT NULL,  -- AutoOnRegistration | Reprint
  printed_by  VARCHAR(100) NOT NULL,
  printed_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  reason      TEXT  -- required for Reprint
);
```

## 8. State Transitions

| From | To | Trigger | Compliance |
|---|---|---|---|
| (new) | Registered + Label Printed | 5 checks passed; barcode auto-printed | ALCOA+ Contemporaneous |
| Registered | Pending Testing | SRF e-sig §11.50 | 21 CFR §11.50 |
| Pending Testing | In Testing | Analyst scans barcode → task opens | GMP Chain of Custody |
| In Testing | Pending QA Review | All steps signed off by analyst | GMP |
| Pending QA Review | Released | QA approves + e-sig | 21 CFR §11.50 |
| Pending QA Review | Rejected | QA rejects + mandatory reason + e-sig | 21 CFR §11.50 |
